# ADR-0004 — AWS real, segurança e entrega incremental

**Estado:** decisão vigente, implementação pendente · **Data:** 19/11/2026

**Decisão.** A POC começa no Hub `kind` com demonstrações locais de Crossplane e `TerraformStack`. Para a primeira execução AWS, a Etapa 07 valida o registro UAT e o acesso humano IAM Identity Center. A Etapa 08 verifica uma sessão temporária de bootstrap STS no Pod `kind` que assume a role UAT, sem access keys permanentes e com cleanup obrigatório; o bootstrap S3 e um Workflow de `init/validate/plan` sem recursos são preparados no Lab 08. A integração do executor à API TerraformStack, à resolução de fontes e ao gate de aprovação para a primeira stack real ficam para a Etapa 09. As roles não são criadas pelo script do laboratório. Em seguida, avalia EKS Auto Mode **um cluster de cada vez** e executa um smoke test. Depois dos clusters, valida a identidade dedicada do Provider AWS no Hub e usa `ObjectStorage` e `Database` em UAT. A implementação de `Database` usa **Amazon Aurora PostgreSQL**, com avaliação de custo, sub-redes, IAM e teardown. PROD é validado como destino separado no exercício de isolamento. A criação automatizada de contas e um controller de Environment ficam para avaliação futura. [Guia de UAT](../../labs/07-registro-ambientes-aws.md) · [Roteiro](../learning-roadmap.md)

**Identidade de laboratório:** credenciais STS de origem são armazenadas apenas temporariamente em um Secret restrito no namespace `argo-workflows` de um Hub `kind` isolado; a role de bootstrap possui somente `sts:AssumeRole` para a UAT. É necessário renová-las manualmente quando expirarem e eliminá-las após a verificação. O Secret não dá renovação automática, nem substitui Pod Identity no futuro EKS. [Etapa 08](../../labs/08-identidade-executor-aws.md) · [IAM](../../foundation/iam/lab08/README.md).

**Governança:** cada operação AWS exige STS para confirmar identidade/conta, região, IAM mínimo, credenciais temporárias, custo, aprovação explícita e plano de cleanup. `apply` e `destroy` nunca estão autorizados por documentação. Terraform state separado por escopo e fora do Git; sem segredos/certificados/kubeconfig reais em commits. Remoção de registro YAML não deleta conta AWS. EKS destrutivo exige gate. Capabilities precisam de política de retenção/deletion testada; finalizers não são aprovação humana.

**Riscos:** validar operators/agentes, custos e requisitos PCI antes de Auto Mode. Um Argo CD não deve administrar PCI/Non-PCI sem revisão dos limites administrativos. Comprovar tentativas indevidas negadas entre Domain e conta/Environment. Observar drift, logs, eventos e trilha de auditoria.
